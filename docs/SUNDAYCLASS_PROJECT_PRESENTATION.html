Project Overview

What Sundayclass Solves

Operational problem

  • Churches need a simple system to manage Sunday class students, centers, attendance, and teacher workflows.
  • Existing flows are often manual, inconsistent, and not built around real ministry structures.
  • Many churches conduct classes both at church level and at local house-based area centers.

Product answer

  • One platform for many churches
  • Each church has isolated data and branding
  • Supports church-level class and many centers like A1, A2, A3
  • Mobile-first attendance and admin-ready reporting
Church Admin Teacher Volunteer Center-Based Ministry White-Label SaaS
Vision

Target Product Direction

Platform -> Churches -> Branding -> Members -> Centers -> Students -> Attendance -> Spotlight -> Reports -> Settings Church -> Church-level Sunday class -> Area centers (A1, A2, A3...) -> Teachers / volunteers -> Students by center -> Attendance by center
Final runtime behavior should be membership-driven: after login, the app resolves the correct church from the user’s UID and membership data, not from a hardcoded env church.
Architecture

Core System Flow

1
User logs in

Firebase Authentication identifies the user by UID.

2
Membership resolves church

The app reads `users/{uid}` and `churches/{churchId}/members/{uid}` to determine church access and role.

3
Branding loads dynamically

Church branding comes from `churches/{churchId}/settings/branding` and applies across web and mobile.

4
Church-scoped data loads

Students, attendance, spotlight, and centers come only from `churches/{churchId}/...` collections.

Storage Strategy

Recommended Backend Direction

Recommended for now

  • Firebase Auth
  • Firestore
  • Keep current media flow stable first
  • Do not migrate storage until platform behavior is validated end to end

Why not change now?

  • Storage migration adds risk before tenant architecture is fully stabilized.
  • The higher priority is runtime church resolution, memberships, data cleanup, and operational testing.
  • Storage can be standardized later without changing product direction.
Recommendation: stabilize the product foundation first, then decide whether to standardize on Firebase Storage or retain a separate media delivery path.
